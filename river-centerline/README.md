# 断裂长条形状（河流）修复 + 中心线提取

给定一张二值栅格：**一条长条形目标（河流）远看连续、实际被随机切断成若干碎片**，旁边还有
椭圆 / 细长矩形 / 小条带 / 随机块 / 近岸湖 / 盐噪声等干扰形状。本目录给出：

1. **修复算法**（把断成长条的碎片重新接成一条连通长条，且不把旁边干扰并进来）
2. **中心线提取算法**（骨架 + 测地最长路径 + 法向剖面亚像素细化，同时给出宽度剖面）
3. **交互式可视化网页**（单文件、离线可用，含分阶段动画、方法对比、误差/宽度曲线）

---

## 3. 算法（方法 B：碎片链重建）

```
输入掩膜
 ├─1 去噪         面积 < 18px 的孤立斑点剔除
 ├─2 碎片几何分析  逐碎片“局部骨架化”→“测地最长路径”→得到
 │                  长度 L=骨架弧长、厚度 t=面积/L、伸长率 L/t、两端点、端点外指切向
 ├─3 弧外推配对    对每个端点用 Kasa 圆拟合（退化时线性）把骨架沿曲率外推 gap 距离，
 │                  要求“A 外推落在 B 端点上”且“B 外推落在 A 端点上”，
 │                  再叠加 4 道约束：间距≤24px、方向偏差≤75°、厚度比≤2.6、外推残差硬上限 2.2t+8
 ├─4 互斥配对      38 条候选按代价升序做全局贪心匹配（每个端点最多配一次），
 │                  代价 = 间距 + 0.6·外推残差 + 0.25·方向偏差
 ├─5 长条判据      串成链后按 总长/平均厚度 ≥ 9 判定“这确实是一条长条”，否则弃用
 ├─6 桥接          相邻碎片端点间画等宽“连接管”（半径 = 0.525·两端平均厚度）
 ├─7 骨架化        Zhang-Suen 细化 + 毛刺剪枝（阈值与局部宽度挂钩）
 ├─8 中心线        骨架图上双端 Dijkstra 求测地最长路径 → 重采样 → 滑动平均
 ├─9 亚像素细化    沿中心线法向扫描掩膜：**中心**取"包含当前点的连续掩膜区间"中点
                   （亚像素；扫描半径按局部 EDT 收窄到 2·dt+2、位移限幅 0.5·dt+1 防跑偏；
                   中心点若落在掩膜外先吸附回最近像元），迭代 4 次收敛；
                   **宽度**取窗口内 EDT 双线性峰值 ×2（只与到岸距离有关，法向偏斜不放大）
```

### 关键设计决策（都是踩坑后改的）

| 坑 | 现象 | 解决 |
|---|---|---|
| 用 PCA 主轴当碎片方向 | 弯曲碎片的主轴与端点实际走向无关，配对全被拒 | 改为**骨架弧长/端点切向**描述子 |
| 用端点附近 5px 差分当切向 | 弯道处切向误差 30°+，河流链接不起来 | 改为**Kasa 圆拟合 + 曲线外推**（直线退化时自动转线性） |
| 固定阈值判"外推吻合" | 河湾极值点曲率符号翻转，残差 10px+ 被误拒 | 硬阈值放宽 + **全局最小代价互斥配对**，让最优链自然胜出 |
| 直连桥接 vs 弧线桥接 | 弧线外推两端各带偏置，融合后鼓出，误差反而更大 | 实测对比后**保留直连等宽管**（外推弧只用于解释/可视化） |
| 法向剖面用 `round` 取像素 | 半像素系统偏移 0.5px（直带中心线偏 0.625px） | 改用 `floor`；再配合下面的"跨度中点"后，直带偏差 0.001px（`test_predict.py` 守着） |
| 法向扫描固定 ±40px | 真实影像的细河上，切向稍有偏差扫描就"顺着河道"跑几十像素，宽度高估 4~10 倍，细化迭代还会滚雪球 | 扫描半径按**局部 EDT 限幅**（真半宽不可能超过到背景的距离）+ 中心点吸附回掩膜 |
| EDT 平台上取峰点 | 偶数宽河道 EDT 是两像元并列的平台，"取最大点"会把中心线顶偏 0.25~1.0px（实测 0.978px） | 用**连续掩膜区间的中点**定中心（`test_predict.py::test_centerline_subpixel` 从 0.978px 降到 0.001px） |
| 评测函数逐环重置最优值 | 返回偏大的距离，指标虚高（把真实 0.34px 报成 1.4px） | 修 `PolyDist.nearest` 跨环保留 best |

### 对照方法 A（形态学闭运算 + 长条连通域筛选）

先膨胀后腐蚀把断裂"糊"起来，再按伸长率/长度挑最大连通域。实现 20 行，但**"一视同仁地糊"**
会把距离近的干扰形状一起并进来，半径越大越严重（见下方指标）。

## 4. 量化结果（seed=7，300×200，河流被切成 7 段，缝宽 5~11px）

场景：输入连通域 85 个（其中盐噪声 37 个），真实河流碎片 13 个（含 1 个 34px 的随机块干扰）。

**方法 B**

| 指标 | 值 |
|---|---|
| 入选碎片链 | `[49, 19, 11, 15, 39, 60, 65]`（7 段，全部是真河流碎片） |
| 链总长 / 平均厚度 / 长条比 | 352.9px / 5.10px / **69.3**（阈值 9） |
| 桥接处数 / 跨接缝隙总长 | 6 处 / 69.2px |
| 修复后连通域数 | **1**（理想值） |
| 误并入干扰像素 | **0 px** |
| 中心线长度 | 407.0px（真值 398.5px） |
| 中心线误差 | 均值 **0.45px**、中位 0.39px、P95 1.24px、最大 2.93px |
| 预测→真值 覆盖@2px / @3px | **98.2%** / 100.0% |
| 真值→预测 覆盖@2px | **98.5%**（几乎覆盖整条河） |
| 宽度 RMSE / 平均宽 | **0.36px** / 预测 5.20px vs 真值 5.05px |
| 耗时 | 0.05s（纯 numpy，无深度学习） |

**方法 A（每个半径取最好的一次）**

| r | 连通域 | 误并入干扰 px | 中心线长 px | 均值误差 px | P95 px | 真值→预测覆盖@2px | 宽度 RMSE px |
|---|---|---|---|---|---|---|---|
| 1 | 13 | 0 | 108.8 | 0.33 | 0.52 | 27.6% | 0.14 |
| 2 | 10 | 806 | 176.9 | 9.50 | 26.52 | 20.1% | 3.74 |
| 3 | 8 | 806 | 173.0 | 9.78 | 26.28 | 18.3% | 4.04 |
| 4 | 6 | 198 | 157.7 | 1.31 | 9.31 | 35.1% | 1.58 |
| 5 | 5 | 198 | 156.7 | 1.34 | 9.14 | 33.8% | 2.30 |
| 6 | 5 | 198 | 159.1 | 0.95 | 4.98 | 35.1% | 2.32 |
| 7 | 5 | 198 | 158.5 | 1.10 | 6.02 | 33.8% | 3.25 |
| 8 | 3 | 973 | 297.7 | 2.60 | 10.57 | 45.1% | 7.04 |

读法要点（避免误读指标）：

* **r=1 看着"误差最小"是假象**：缝宽 5~11px 根本糊不上，只选到最长的一段（109px），
  此时"真值→预测覆盖"只有 27.6%——即 3/4 的河道根本没覆盖到。
* r=2~3 把近岸的椭圆/小条带一起并进来（误并 806px），中心线被拉到干扰形状上（P95 26.5px）。
* r=8 把三类干扰全并进来（973px），"中心线"被扯到干扰块上，长度虚增到 297.7px、宽度 RMSE 7.0px。
* 只有方法 B 同时做到：连通域 = 1、误并 = 0、真值覆盖 98.5%、误差 < 1px。

真值基线：直接从**未断裂**的完整河流掩膜提中心线，误差均值 0.33px / P95 0.54px / 覆盖 100%——
说明方法 B 的 0.45px 主要来自跨缝隙的 6 处桥接（最大 2.93px 出现在两处弯道桥接点），
而不是算法本身有系统偏差。

## 6. 参数（`river_repair.py` 顶部常量）

| 参数 | 默认 | 含义 |
|---|---|---|
| `AREA_MIN_FRAG` | 18 | 去噪面积阈值（低于此视为噪声斑点） |
| `AREA_MIN_LINK` | 20 | 参与配对的最小碎片面积 |
| `ELONG_MIN_LINK` | 1.55 | 参与配对的最小伸长率（长度/厚度） |
| `GAP_MAX` | 24 | 允许桥接的最大端点间距(px) |
| `ANGLE_MAX` | 75° | 方向偏差硬上限 |
| `PRED_REACH` | 16 | 弧外推时向内取用的骨架弧长(px) |
| `ERR_HARD_K/B` | 2.2 / 8.0 | 外推残差硬上限 = K·平均厚度 + B |
| `THICK_RATIO_MAX` | 2.6 | 相邻碎片厚度比上限 |
| `STRIP_RATIO` | 9 | 长条判据：链长/平均厚度 |

调参建议：缝宽更大 → 调大 `GAP_MAX` 与 `ERR_HARD_K`；河流更细/更弯 → 调小 `PRED_REACH`
（弧外推更贴局部曲率）；干扰更贴近河流 → 调小 `ERR_HARD_K`、调大 `STRIP_RATIO`。

## 7. 已知局限与可扩展方向

1. **交点 / 河网（Y 形分叉）**：当前判据是"一条链"，分叉口会出现 3 个端点竞争配对。可把互斥配对换成**最小生成树 + 度约束**，或换成"先聚类成骨架图再剪枝"。
2. **环路**：`chains_from_matches` 已能处理度=2 的闭环，但长条判据只认开链。
3. **缝宽接近甚至超过干扰间距**时，单靠几何一致性会退化——可加**全局曲率延续性**（如样条平滑能量）或颜色/高程等额外通道做联合判据。
4. **分辨率**：亚像素细化假设形状是各向同性带状；对亚像素级超细河（宽 < 3px）应先用距离场加权而不是二值区间。
5. **三维/多维**：本实现是 2D 栅格；推广到 3D 时骨架换成 3D 细化、法向剖面换成切平面扫描即可，其余（外推配对、长条判据）可直接复用。

* **命令行**：`qgis/river_centerline_cli.py`（无需 QGIS/GDAL）
* **QGIS 插件**：`qgis/pi_river_centerline/`（工具栏对话框 + 两个 Processing 算法，可批处理/建模型）

### 相比网页版新增的能力

| 能力 | 说明 |
|---|---|
| **多目标** | `extract_rivers` 把**所有**碎片链 + 独立长条都当候选，逐条在包围盒内修复、骨架化、细化，输出 N 条中心线（每条带 `river_id`）；单目标仍是原来的"最长一条链" |
| **影像判读水体** | `raster_mask.py`：`blue/loose/cyan/hsv_water/dark` 五条纯像素规则，`auto` 用"线状证据（伸长率≥3 的成分占多少像素）"自动挑规则 |

### 真实影像实测（2569×2302，RGBA，EPSG:3857，像元 10m）

浅米色制图底图 + 淡蓝水系细线，水体仅占 1.44%，76 个连通域（含 12 个噪声小斑）：

| 指标 | 结果 |
|---|---|
| 输出中心线 | **32 条**（最长 3 228 px ≈ 32.3 km） |
| 中心线总长 | 20 088 px ≈ 201 km |
| 河宽 | 平均 4.37 px（1.42~31.06 px），剖面/等效宽度比值中位数 1.068 |
| 桥接 | 22 处，新增 594 px 水体 |
| 贴合度 | 99.50% 采样点在离水体 ≤1px（99.74% ≤2px） |
| 耗时 | 算法 ~9 s（含全部矢量/报告落盘约 18 s） |

### 真实数据暴露并修掉的两个算法坑

| 坑 | 现象 | 解决 |
|---|---|---|
| 法向剖面固定扫 ±40px | 细河上切向稍有偏差，扫描就"顺着河道"跑几十像素，宽度被高估 4~10 倍，且细化迭代把误差滚雪球 | 扫描半径用**局部 EDT 限幅**（真半宽不可能超过到背景的距离）+ 中心点吸附回掩膜 |
| 用区间中点 + 大扫描半径当新中心 | 宽水体（EDT 大→窗口大）相邻点朝相反方向漂移形成锯齿，中心线长度和宽度一起被放大（骨架 512px → 输出 1350px） | 扫描半径按局部 EDT 收窄 + 位移限幅；宽度不再用区间长度，而与"面积÷长度"的等效宽度一致（比值中位数 1.07） |
| 只用 EDT 峰点定中心 | EDT 在偶数宽河道上是两像元并列的平台，中心被顶偏 0.978px（网页版 `test_predict.py` 抓到） | 中心改回**连续掩膜区间中点**（亚像素），偏差 0.001px；两处对同一函数的要求（真实数据要稳、合成真值要准）都由这一版满足 |

多目标的"一条河"由门槛参数定义（最小中心线长度/水体面积/长条比）；
断口大于 `--gap-max` 的两段刻意**不合并**（宁可分成两条，也不把两条不同的河错并成一条）。
